### 1.1 文档定位

本文档不是为了把所有页面重新画一遍，而是明确作品集中必须展示哪些任务、页面和状态，并指导现有小程序页面的截图、补画及可用性验证。

现已依据本规格生成15张关键高保真代码原型V1。正式交付分为两层：

1. 本文档：页面范围、信息架构、任务流、状态与证据说明。
2. 视觉资产：`assets/prototype-v1`中的可编辑HTML/CSS/JS源文件、15张单页PNG和总览图。

### 1.2 能力真实性标签

| 标签 | 含义 | 原型表达 |
|---|---|---|
| 【代码事实】 | 页面、调用或业务结构可在代码中核验 | 可展示现有界面，但不扩大能力结论 |
| 【真实接口】 | 主后端存在对应接口和业务数据 | 标注接口来源及仍待联调项 |
| 【规则实现】 | 通过确定性阈值/规则判断 | 不包装为已完成AI模型 |
| 【外部依赖】 | 依赖第三方ASR/TTS/LLM等服务 | 标注失败和降级状态 |
| 【模拟验证】 | 接口或界面存在，但结果/执行为模拟 | 使用醒目标识，不作为真实成果 |
| 【待联调】 | 前后端或硬件结构存在，真实闭环未确认 | 展示“执行未确认”等状态 |
| 【复盘补充】 | 为完整产品闭环新增的原型状态 | 说明不是实习期既有交付 |
| 【产品规划】 | 后续探索，不进入当前验收 | 使用弱化视觉并避免可点击假象 |

## 2. 原型策略

### 2.1 展示原则

- 正文只展示能说明产品判断的关键页面，不用37个页面堆砌工作量。
- 每条主路径同时展示正常、异常、权限和降级状态。
- 页面必须显示数据更新时间、设备状态和判断可信边界。
- 模型标签、场景事件和产品告警分层呈现。
- 高风险事件突出人工查看和处理，不暗示AI替代监护人。
- 原型不可访问时，飞书文档仍能通过截图和说明独立理解。

## 4. 全局页面框架

### 4.1 看护页信息优先级

```text
L3紧急告警
→ L2关注告警
→ 设备离线/数据无效
→ 当前主场景及伴随状态
→ 视频与传感器数据
→ 最近事件和功能入口
```

### 4.2 全局状态组件

| 组件 | 展示内容 | 操作 |
|---|---|---|
| 设备状态条 | 在线/延迟/离线、最后更新时间 | 查看排障 |
| 数据质量标识 | 有效/降级/无效及原因 | 查看可用能力 |
| 主场景卡 | 熟睡、哭闹、疑似危险等 | 进入事件详情 |
| 伴随状态标签 | 趴睡、站立、哭闹等 | 查看判断依据 |
| 告警卡 | 等级、时间、触发依据和状态 | 查看、确认、处理 |
| 响应状态条 | 待下发/执行中/成功/未确认 | 重试或人工处理 |

### 4.3 全局文案原则

- 未经人工确认的高风险结果统一使用“疑似”。
- 数据过期时显示“最后更新时间”，不用绿色“正常”掩盖离线。
- “接口请求成功”不能显示“设备执行成功”。
- 生理数据只展示测量值和设备状态，不输出疾病判断。
- AI报告明确“AI生成，仅供育儿记录参考”。

## 5. 任务流一：首次使用与设备绑定

### 5.1 任务目标

用户完成家庭、宝宝、设备和网络配置，并确认设备真实上线和首次有效数据。

```text
登录 → 创建/加入家庭 → 添加宝宝 → 扫码/输入SN
→ 设备校验 → WiFi配置 → 绑定关系写入
→ 等待首次心跳 → 首次有效数据 → 进入看护页
```

### 5.2 页面规格

| 页面 | 关键内容 | 主要操作 | 能力标记 |
|---|---|---|---|
| 开箱步骤页 | 进度、用途、权限说明 | 下一步/暂时跳过 | 【代码事实】 |
| 宝宝档案 | 姓名代称、月龄、关系 | 保存 | 【真实接口结构】 |
| 设备校验 | 扫码/SN、设备状态 | 校验设备 | 【部分实现】 |
| WiFi配置 | SSID、密码、隐私提示 | 开始配网 | 【待真实硬件联调】 |
| 绑定结果 | 云端绑定与设备上线分离 | 重试/进入看护 | 【复盘补充】 |

### 5.3 必须补齐的状态

| 状态 | 页面表达 | 后续动作 |
|---|---|---|
| SN错误 | “未找到该设备，请检查编号” | 保留输入并重试 |
| 设备已绑定 | “设备已属于其他家庭” | 联系管理员，不泄露对方信息 |
| 权限拒绝 | 说明蓝牙/网络/扫码用途 | 打开系统设置 |
| 配网失败 | 区分密码、信号、超时等原因 | 针对性排障 |
| 绑定成功但离线 | “已绑定，设备尚未上线” | 继续等待/重新配网 |
| 首次无数据 | “设备在线，正在等待有效数据” | 查看传感器状态 |

### 5.4 成功条件与埋点

- 成功条件：绑定关系唯一、设备首次在线、至少一种P0感知数据通过质量校验。
- 关键埋点：`device_bind_started`、`device_bind_result`、`device_online_changed`、`sensor_data_received`、`first_monitoring_activated`。
- 关联需求：DEV-001、MON-001。

## 6. 任务流二：日常看护与熟睡

### 6.1 任务目标

用户快速理解当前看护是否可信，并查看稳定熟睡状态，而不是看到一个无时间依据的单帧标签。

### 6.2 实时看护正常页

页面至少展示：

- 当前宝宝和设备。
- 在线状态及最后更新时间。
- 当前主状态“熟睡”和伴随姿态“仰卧/侧卧/趴卧”。
- 状态持续时长和“连续数据确认”说明。
- 视频或不可用原因。
- 呼吸、心率、活动等数据及单位、更新时间和非医疗声明。
- 最近事件、预警规则和设备入口。

### 6.3 熟睡状态规则表达

不直接展示“模型置信度92%＝宝宝一定熟睡”，推荐表达：

```text
当前状态：熟睡
已持续：42分钟
判断依据：活动度较低、姿态稳定、连续有效数据
数据状态：刚刚更新
```

模型分数放在测试/调试视图，不作为家长端主要语言。

### 6.4 异常状态

| 状态 | 页面主文案 | 禁止行为 |
|---|---|---|
| 数据加载中 | 正在获取设备数据 | 默认显示正常 |
| 数据延迟 | 数据更新延迟，最后更新于XX:XX | 使用“实时”标识 |
| 设备离线 | 设备已离线，当前状态不可用 | 继续显示熟睡 |
| 摄像头异常 | 画面不可用，视觉判断能力下降 | 输出确定性姿态 |
| 雷达异常 | 生理/活动数据不可用 | 显示过期数值为最新 |
| 多模态冲突 | 检测结果存在冲突，请人工查看 | 强制选择单一状态 |
| 权限不足 | 当前账号无实时画面权限 | 暴露画面缩略图 |

### 6.5 成功条件与埋点

- 成功条件：用户能在5秒内判断设备是否在线、数据是否最新、宝宝主状态及是否需要介入。
- 关键埋点：`scene_event_started`、`scene_event_updated`、`scene_event_ended`、`device_online_changed`。
- 关联需求：MON-001、SLP-001。

## 7. 任务流三：哭闹告警闭环

### 7.1 任务目标

系统发现持续哭闹后，通过分级、去重和可解释信息通知照护者；用户可以确认、处理或标记误报。

```text
哭闹候选 → 持续条件成立 → L1/L2/L3分级
→ 告警送达 → 用户查看 → 确认/误报/无法判断
→ 响应或人工处理 → 事件关闭 → 进入时间线
```

### 7.2 L2告警卡片

| 信息 | 示例表达 |
|---|---|
| 等级 | L2 需要关注 |
| 场景 | 检测到持续哭闹 |
| 时间 | 21:36，已持续约45秒 |
| 依据 | 持续哭声，并伴随明显动作 |
| 数据质量 | 声音有效；视频可用/不可用需明确 |
| 操作 | 查看实时状态、确认、播放预设音频 |

分贝和模型分数可在“查看依据”中显示，不作为主文案。未经设备校准的阈值应标注为候选规则。

### 7.3 事件详情

- 事件时间轴：候选、成立、告警发送、送达、查看和处理。
- 主场景：哭闹；伴随状态：坐起、站立等。
- 判断依据和数据质量。
- 实时画面/事件快照，受权限和隐私约束。
- 操作：确认真实、误报、无法判断、处理完成。
- 响应状态：未执行、执行中、成功、失败或未确认。

### 7.4 误报与告警疲劳

- 误报原因可选：电视/成人声音、笑声、其他儿童哭声、画面/音频异常、其他。
- 同一持续哭闹只展示一个主事件；新证据追加到时间轴。
- 短时间反复命中使用冷却和事件合并，不重复弹出强提醒。
- 用户关闭提醒时说明可能影响，并区分L1与L2/L3权限。

### 7.5 异常状态

| 异常 | 原型表现 |
|---|---|
| 告警发送失败 | 显示系统重试/备用渠道状态，不假装送达 |
| 用户未确认 | 显示倒计时或“即将升级联系人” |
| 音频响应未授权 | 引导家长授权，不自动播放 |
| 硬件无回执 | “响应未确认执行，请人工查看” |
| AI低置信度 | “疑似哭闹，请查看实时状态” |

### 7.6 成功条件与埋点

- 成功条件：用户理解为什么提醒、能完成明确反馈，且同一事件不重复轰炸。
- 埋点：`alert_created`、`alert_send_result`、`alert_delivered`、`alert_viewed`、`alert_confirmed`、`scene_feedback_submitted`、`event_handling_completed`。
- 关联需求：ALT-001、CRY-001、RSP-001。

## 8. 任务流四：危险动作L3闭环

### 8.1 任务目标

优先让照护者发现疑似身体越界或攀爬护栏，并完成查看、确认、升级和处理；原型不得把模型单帧结果包装成确定事实。

```text
风险特征命中 → 疑似危险候选 → 连续/多特征规则成立
→ L3告警 → 强提醒并送达 → 用户确认
→ 未确认则升级备用联系人 → 人工处理 → 事件关闭
```

### 8.2 L3强提醒页

页面信息顺序：

1. 红色风险等级与“疑似危险动作”。
2. 宝宝、设备、发生时间及已持续时间。
3. 触发依据：如身体部分越过护栏区域、向外攀爬。
4. 数据质量和最后更新时间。
5. 实时查看主按钮。
6. “我已查看”与“标记误报/无法判断”。
7. 未确认升级说明。

禁止使用高频闪烁或无法中止的高音量刺激；视觉强调必须符合可访问性和婴幼儿家庭使用环境。

### 8.3 主场景与伴随状态

示例：

```text
主告警：疑似危险动作
伴随状态：站立、哭闹
依据：靠近护栏＋向外攀爬动作连续出现
```

这体现多维标签而非九选一，危险动作在展示和处理上优先，但不删除伴随信息。

### 8.4 超时升级

- 告警送达后开始确认计时，具体时限标记“待试点确定”。
- 首位联系人未确认时通知备用联系人并更新状态。
- 任一授权照护者确认后，其他终端同步“已由XX确认”。
- 确认不等于已处理；必须继续提交处理结果或事件解除信息。

### 8.5 异常与降级

| 状态 | 页面表达 |
|---|---|
| 画面遮挡但风险信号存在 | “无法确认的疑似异常，请立即查看” |
| 成人抱起干扰 | 提供“成人正在照护”反馈，不直接关闭审计记录 |
| 消息未送达 | 使用备用渠道/联系人，并记录失败 |
| 多端同时确认 | 接受首次有效确认，其余显示处理人和时间 |
| 事件已解除但无人确认 | 保留事件记录，标注“已解除、未人工确认” |
| 网络断开 | 展示最后状态和离线风险，不显示当前安全 |

### 8.6 成功条件与埋点

- 成功条件：用户在强提醒中快速理解风险、查看实时状态并完成确认；超时路径能够升级。
- 埋点：`scene_event_started`、`alert_created`、`alert_delivered`、`alert_confirmed`、`alert_escalated`、`event_handling_completed`、`event_archived`。
- 关联需求：DNG-001、ALT-001、RSP-001。

## 9. 任务流五：场景响应与人工覆盖

### 9.1 响应状态

| 状态 | 页面文案 | 操作 |
|---|---|---|
| 待下发 | 正在准备设备响应 | 取消 |
| 已下发 | 指令已发送，等待设备接收 | 等待/人工处理 |
| 执行中 | 设备正在执行 | 立即停止 |
| 执行成功 | 设备已返回执行成功 | 查看记录 |
| 执行失败 | 设备执行失败：原因 | 重试/人工处理 |
| 未确认 | 未收到设备回执 | 重试/人工处理 |
| 用户中止 | 已由用户停止 | 返回事件详情 |

### 9.2 配置页

用户配置音频、灯光、屏幕或设备模式时，应显示：

- 适用场景和风险等级。
- 是否自动执行。
- 授权状态、音量/时长及中止方式。
- 设备支持能力和在线状态。
- 安全提示及恢复默认入口。

L3危险动作默认以人工处理为主，自动响应不得替代告警和确认。

### 9.3 埋点与关联

- 埋点：`device_command_created`、`device_command_sent`、`device_command_ack`。
- 关联需求：RSP-001。
- 验收事实：只有相同`command_id`的硬件终态回执才显示执行成功。

## 10. 任务流六：成长报告

### 10.1 任务目标

用户查看由结构化事件生成的睡眠、哭闹、风险和里程碑总结，并能够理解数据覆盖、AI来源及纠错方式。

### 10.2 页面结构

1. 报告周期和数据覆盖率。
2. 睡眠时长、片段和状态稳定性。
3. 哭闹事件、持续时间和家长反馈。
4. 关注/危险事件及处理结果。
5. 成长里程碑和温馨瞬间。
6. AI摘要、来源说明和非医疗声明。
7. 查看依据、反馈纠错和分享权限。

### 10.3 必须补齐的状态

| 状态 | 页面表达 |
|---|---|
| 数据充分 | 展示完整结构化报告及来源事件 |
| 数据不足 | 展示覆盖率和简版概览，不生成确定趋势 |
| 外部LLM失败 | 使用规则化摘要，标记生成方式 |
| 内容待纠错 | 提供事实错误、表达不当等反馈入口 |
| 重新生成 | 保留版本记录，不静默覆盖 |
| 无分享权限 | 阻止分享并引导管理员授权 |

### 10.4 埋点与关联

- 埋点：`report_generation_started`、`report_generation_result`、`report_viewed`、`report_feedback_submitted`。
- 关联需求：RPT-001。
- 能力标签：【部分实现＋外部LLM依赖＋失败兜底】。

## 11. AI陪伴原型边界

AI陪伴为P2，正文只展示一张“能力边界与降级”示意，不占用安全闭环主叙事。

| 状态 | 原型要求 |
|---|---|
| 正常对话 | 显示正在聆听、理解、生成和播放状态 |
| ASR低置信度 | 请求重新表达，不虚构理解结果 |
| LLM超时 | 使用固定安全话术或结束对话 |
| TTS失败 | 展示文字或播放授权的预设内容 |
| 内容风险 | 拦截并提供安全替代回复 |
| 外部服务中断 | 关闭陪伴能力，不影响P0看护和告警 |

能力标记：【迁移原型＋外部依赖】；不得写成主系统已完成生产集成。

## 13. 可用性测试方案

### 13.1 测试对象

- 5—8名有婴幼儿看护经验的目标用户进行第一轮定性测试。
- 至少覆盖主要照护者和协同照护者。
- 危险场景使用模拟画面和测试设备，不让真实婴幼儿执行危险动作。

### 13.2 核心任务

| 任务 | 成功标准 | 重点观察 |
|---|---|---|
| 完成设备绑定 | 独立完成并理解在线与绑定的区别 | 权限、配网、失败恢复 |
| 判断当前是否可信 | 5秒内找到在线、更新时间和数据质量 | 是否把过期数据当实时 |
| 处理哭闹告警 | 查看依据并完成确认/反馈 | 是否理解告警等级和误报入口 |
| 处理L3危险告警 | 快速查看、确认并理解升级机制 | 是否误触关闭、是否知道下一步 |
| 处理无回执 | 识别设备未确认执行并选择人工处理 | 是否把接口成功当硬件成功 |
| 查看报告依据 | 找到来源事件和纠错入口 | 是否把AI摘要当医疗结论 |

### 13.3 记录指标

- 任务完成率、完成时间、错误数和求助次数。
- 关键文案理解率。
- L3告警首次正确操作率。
- 主观难度（1—5分）和信任度反馈。
- 误操作路径及用户原话。

第一轮测试用于发现问题，不用5—8人的小样本声称统计显著性。

## 17. 阶段结论

现有小程序已经提供较完整的页面骨架，但高保真作品集不能只展示正常页面。T0.1原型应围绕“设备可信上线—实时状态可信—哭闹/危险告警可解释—响应有回执—结果可沉淀”补齐关键状态。

本版已经完成原型范围、页面规格、任务流、异常状态、真实性标签、数据映射和验收设计，并输出15张关键高保真代码原型V1。后续仍可根据可用性测试结果迭代文案、层级与交互，不将V1模拟页面表述为真实算法或硬件已经上线。
