## 3. 公共业务规则

### 3.1 核心对象

| 对象 | 关键属性 |
|---|---|
| 用户 | 用户ID、身份、授权状态 |
| 家庭 | 家庭ID、管理员、成员与权限 |
| 宝宝 | 宝宝ID、月龄、基础信息、监护授权 |
| 设备 | 设备ID/SN、绑定状态、在线状态、固件版本 |
| 传感器数据 | 来源、字段、单位、采集时间、上传时间、质量状态 |
| 场景结果 | 场景、分数、规则/模型版本、数据质量、开始与结束时间 |
| 事件 | 事件ID、风险等级、状态、证据摘要、关联宝宝与设备 |
| 告警 | 告警ID、渠道、发送/送达/查看/确认状态 |
| 响应指令 | 指令ID、目标设备、动作、状态、回执和失败原因 |
| 成长报告 | 周期、来源事件、生成方式、版本与可见范围 |

### 3.2 时间与链路追踪

- 设备采集时间、服务端接收时间、判断完成时间、告警发送时间、渠道送达时间必须分开记录。
- 每个P0事件生成唯一`event_id`；告警、响应、用户确认及报告均关联该事件ID。
- 同一设备发生时间回拨或时钟漂移时，标记数据异常，不直接参与正式延迟统计。
- 页面必须展示最后更新时间，过期数据不得标为“实时”。

### 3.3 数据质量状态

| 状态 | 定义 | 系统行为 |
|---|---|---|
| 有效 | 关键字段完整、时间有效、数值和信号质量合格 | 可进入规则/模型判断 |
| 降级 | 部分模态缺失，但存在明确的降级规则 | 输出受限结果并提示能力下降 |
| 无效 | 关键数据缺失、过期、冲突或质量过低 | 不输出确定性状态 |
| 离线 | 设备超过心跳阈值未上报 | 停止实时结论并通知用户 |

### 3.4 权限规则

- 仅设备管理员可绑定、解绑、转移设备及管理家庭成员。
- 仅获得对应权限的成员可查看实时视频、告警和成长报告。
- 规则修改、视频访问、敏感数据导出和删除必须留审计记录。
- 权限撤销后立即失去访问权；已下载内容的风险需在授权提示中说明。

### 3.5 幂等、重试与去重

- 绑定、事件创建、告警发送和响应指令必须支持幂等标识。
- 网络重试不得重复创建设备关系、事件或告警。
- 同一持续事件默认只生成一个主事件，可追加状态更新，不重复轰炸用户。
- 失败重试需限制次数并记录最终失败原因，禁止无限重试。

## 4. 多维标签与九场景映射

### 4.1 设计结论

【口头信息｜待材料核验】据原项目产品经理说明，开发团队曾基于九类标签微调VL模型，各类别识别结果据称均在90%以上；当前尚未取得模型版本、样本量、逐类Precision/Recall、混淆矩阵及独立测试报告。

【复盘方案】九大场景并非完全互斥。T0.1采用“底层多维事实标签＋上层九场景映射＋风险告警”的结构，现有九分类结果保留为对照基线，不直接宣称推翻或重做原模型。

### 4.2 建议标签维度

| 维度 | 标签示例 | 标注说明 |
|---|---|---|
| 睡眠/意识 | 熟睡、清醒、状态转换、无法判断 | 状态转换需标记前后状态及时间 |
| 身体姿态 | 躺卧、坐起、站立、不适用、无法判断 | 不强制所有维度只有三个值 |
| 卧姿方向 | 仰卧、侧卧、趴卧、不适用、无法判断 | 站立或坐起时可标不适用 |
| 动作 | 静止、翻身、攀爬、身体越界、其他 | 动作应标开始和结束时间 |
| 情绪/声音 | 平静、高兴、哭闹、无法判断 | 哭闹以音频为主，视觉为辅助 |
| 空间/风险 | 正常、靠近护栏、越过护栏、关注、紧急 | 风险标签需有明确依据 |
| 数据质量 | 有效、遮挡、过暗、噪声、缺失 | 用于降级与评测切片 |

人工标注提供事实标签，不填写模型置信度。模型推理后输出预测分数；只有完成置信度校准后，预测分数才可谨慎解释为概率。

### 4.3 九场景映射示例

| 产品场景 | 底层维度组合 | 是否可与其他场景并存 |
|---|---|---|
| 熟睡 | 熟睡＋躺卧＋低活动＋持续有效 | 可与侧睡/趴睡并存 |
| 侧睡/趴睡 | 躺卧＋侧卧或趴卧＋持续时间 | 可与熟睡、哭闹并存 |
| 刚睡醒 | 熟睡转清醒＋动作增加 | 可与坐起并存 |
| 坐起 | 姿态由躺卧转为坐起并持续 | 可与哭闹、高兴并存 |
| 翻身 | 姿态方向发生连续变化 | 可与靠近床沿并存 |
| 站立 | 姿态为站立并持续 | 可与哭闹、危险并存 |
| 高兴玩耍 | 清醒＋活跃动作＋高兴表情/声音 | 可与坐起、站立并存 |
| 哭闹 | 哭声＋持续时间，视觉/动作辅助 | 可与所有姿态及危险并存 |
| 危险动作 | 攀爬/越界/高风险位置＋持续条件 | 作为主风险场景优先展示 |

### 4.4 输出规则

- 同一时刻允许输出多个状态标签和多个产品场景。
- 当危险动作与其他场景并存时，危险动作作为主告警，其他结果作为伴随状态。
- Top3结果仅用于调试、误差分析或人工复核，产品端不机械地只取Top1。
- 模型标签必须经过数据质量、持续时间、事件合并及风险规则后，才能转化为告警。

## 5. 功能一：设备绑定

### 5.1 元数据

| 项目 | 内容 |
|---|---|
| 需求编号 | DEV-001 |
| 优先级 | P0 |
| T0状态 | 【部分实现】页面、业务绑定及相关API结构存在 |
| T0.1目标 | 完成可追踪、可恢复、可防重复的设备绑定闭环 |

### 5.2 用户故事

作为设备管理员，我希望将唯一设备绑定到家庭和宝宝，并确认设备真实在线，以便开始可信的实时看护。

### 5.3 前置条件

- 用户已登录并具有家庭管理员权限。
- 设备SN/二维码可读取，设备处于允许绑定状态。
- 用户已同意必要的网络、蓝牙或摄像头权限。
- 若绑定到宝宝，宝宝档案已创建或在流程中补充。

### 5.4 主流程

```text
进入添加设备 → 扫码/输入SN → 校验设备状态
→ 选择家庭与宝宝 → 配置网络 → 设备确认
→ 云端建立绑定关系 → 获取首次心跳 → 显示绑定成功
```

### 5.5 状态机

```text
未绑定 → 校验中 → 配网中 → 等待设备确认 → 已绑定在线
                    ├→ 已绑定离线
                    └→ 绑定失败/可重试
已绑定 → 解绑中 → 已解绑
```

### 5.6 业务规则

- SN不存在、格式错误或设备已被其他家庭绑定时，不进入配网。
- “云端关系写入成功”与“设备首次在线”分开显示。
- 相同请求重复提交不得创建重复绑定关系。
- 解绑前提示实时看护中断和历史数据影响；解绑操作需二次确认。
- 设备转移需先解除旧家庭授权，不允许静默覆盖。

### 5.7 异常与降级

| 异常 | 处理 |
|---|---|
| 用户拒绝权限 | 说明用途并提供重新授权入口 |
| SN错误/不存在 | 保留输入并明确错误原因 |
| 设备已绑定 | 禁止覆盖，提供联系管理员路径 |
| WiFi配置失败 | 区分密码、信号、设备超时等原因并允许重试 |
| 云端绑定成功但设备离线 | 显示“已绑定，设备尚未上线”，不展示实时看护 |
| 重复点击 | 使用幂等键返回同一结果 |

### 5.8 验收

| 用例 | Given | When | Then |
|---|---|---|---|
| 正常绑定 | 合法管理员、未绑定设备、网络正常 | 完成扫码和配网 | 建立唯一关系并收到首次心跳 |
| 重复绑定 | 设备已属于当前家庭 | 再次提交 | 返回既有关系，不生成重复数据 |
| 已被占用 | 设备属于其他家庭 | 提交绑定 | 阻止操作，不泄露对方家庭信息 |
| 上线失败 | 云端关系已写入但设备无心跳 | 等待超时 | 展示已绑定离线及排障入口 |
| 无权限解绑 | 普通成员登录 | 尝试解绑 | 操作被阻止并记录审计日志 |

## 6. 功能二：实时看护

### 6.1 元数据

| 项目 | 内容 |
|---|---|
| 需求编号 | MON-001 |
| 优先级 | P0 |
| T0状态 | 【部分实现】传感器上传、状态、历史数据及页面结构存在 |
| T0.1目标 | 用户能够区分实时、延迟、降级、无效和离线状态 |

### 6.2 页面信息

- 宝宝及当前设备。
- 设备在线状态、最后更新时间和网络状态。
- 当前主状态及伴随状态。
- 生理/活动数据及单位；候选生理值不得包装为医疗结论。
- 实时视频或不可用原因。
- 当前告警、最近事件和处理入口。

### 6.3 状态优先级

```text
紧急告警 > 关注告警 > 设备离线 > 数据无效/降级 > 正常场景状态
```

当多个场景同时存在时，页面展示一个主状态及若干伴随状态，例如：

```text
主状态：疑似危险动作
伴随状态：站立、哭闹
依据摘要：靠近护栏并出现向外攀爬动作
```

### 6.4 数据新鲜度

- 页面必须展示数据时间戳。
- 超过约定刷新窗口的数据标记为“延迟”；超过离线阈值则进入离线状态。
- 历史补传数据进入历史记录，不覆盖为当前实时状态。
- 多端查看使用同一事件与状态版本，避免一端已处理、另一端仍显示未处理。

### 6.5 异常与降级

| 状态 | 页面行为 |
|---|---|
| 首次无数据 | 显示等待采集，不默认“正常” |
| 数据延迟 | 显示最后更新时间和延迟标识 |
| 设备离线 | 停止实时结论，显示排障入口 |
| 单传感器异常 | 显示能力降级及仍可用能力 |
| 画面遮挡/过暗 | 显示画面质量问题，不输出确定性视觉状态 |
| 权限不足 | 隐藏敏感内容并提供申请授权路径 |

### 6.6 验收

| 用例 | Given | When | Then |
|---|---|---|---|
| 正常看护 | 设备在线且数据有效 | 打开看护页 | 展示当前状态、更新时间及关联设备 |
| 数据过期 | 无新数据超过阈值 | 页面刷新 | 不再标为实时，展示延迟或离线 |
| 单模态故障 | 摄像头不可用、雷达有效 | 查看状态 | 明确降级，不输出依赖视觉的确定性结论 |
| 历史补传 | 恢复网络后补传旧数据 | 后端接收 | 写入历史，不覆盖当前状态 |

## 7. 功能三：异常告警

### 7.1 元数据

| 项目 | 内容 |
|---|---|
| 需求编号 | ALT-001 |
| 优先级 | P0 |
| T0状态 | 【部分实现】事件生成、查询及确认/处理结构存在 |
| T0.1目标 | 跑通事件创建、发送、送达、查看、确认、升级和关闭闭环 |

### 7.2 告警等级

| 等级 | 定义 | 示例 | 用户动作 |
|---|---|---|---|
| L1提醒 | 信息性事件，无需立即介入 | 刚睡醒、轻度哭闹 | 查看或汇总处理 |
| L2关注 | 可能需要及时查看 | 持续哭闹、持续风险姿态 | 查看、确认、采取照护措施 |
| L3紧急 | 疑似高风险，需要立即人工介入 | 攀爬/身体越界 | 强提醒、确认并处理 |

### 7.3 告警状态机

```text
事件成立 → 告警待发送 → 已发送 → 已送达 → 已查看
                                      ├→ 已确认 → 处理中 → 已关闭
                                      ├→ 误报/无法判断 → 已关闭
                                      └→ 超时未确认 → 已升级
发送失败 → 重试中 → 已发送或最终失败/备用渠道
```

### 7.4 告警内容

- 宝宝、设备、事件时间和风险等级。
- 主场景及伴随状态。
- 可理解的触发依据，不展示无法解释的模型内部术语。
- 数据质量和“疑似/已确认”状态。
- 查看实时状态、确认、标记误报和处理完成入口。
- 明确非医疗诊断边界。

### 7.5 去重、冷却与升级

- 同一`event_id`只创建一个主告警，状态变化通过更新或追加记录表达。
- L1可汇总；L2/L3不得被普通免打扰完全静默，具体策略需用户明确授权。
- L2/L3在设定时间内未确认，按联系人顺序升级；时间值需通过试点确认。
- 事件解除不等于用户已处理，二者分别记录。
- 用户反馈“误报”进入评估数据，不自动修改线上模型。

### 7.6 验收

| 用例 | Given | When | Then |
|---|---|---|---|
| L2正常告警 | 哭闹事件成立 | 告警服务处理 | 生成唯一告警并记录发送/送达状态 |
| L3升级 | 危险事件已送达但超时未确认 | 达到升级条件 | 通知备用联系人并记录升级链路 |
| 重复帧命中 | 同一事件连续命中规则 | 多次判断 | 不重复创建告警 |
| 推送失败 | 主渠道不可用 | 发送失败 | 按策略重试/备用渠道并记录原因 |
| 误报反馈 | 用户确认不是实际异常 | 点击误报 | 事件关闭并生成可审计反馈标签 |

## 8. 功能四：场景响应

### 8.1 元数据

| 项目 | 内容 |
|---|---|
| 需求编号 | RSP-001 |
| 优先级 | P1，L3人工响应链路为P0 |
| T0状态 | 【待联调】灯光、屏幕、声音和设备模式接口存在 |
| T0.1目标 | 建立安全、可中止、有真实回执的响应机制 |

### 8.2 响应类型

| 类型 | 示例 | 约束 |
|---|---|---|
| 用户响应 | 查看、确认、处理、联系其他照护者 | 高风险场景的核心响应 |
| App响应 | 页面强提醒、事件说明、操作引导 | 必须显示实时性和疑似状态 |
| 音频响应 | 播放家长预设音频或白噪声 | 需授权、限音量/时长、可中止 |
| 灯光/屏幕 | 低刺激灯光或动画 | 需婴幼儿安全评审 |
| 设备模式 | 切换预设模式 | 必须有真实执行回执 |

### 8.3 指令状态机

```text
待下发 → 已下发 → 设备已接收 → 执行中 → 执行成功
                 ├→ 超时 → 重试/人工处理
                 ├→ 执行失败
                 └→ 用户中止
```

后端接口返回成功仅代表请求被服务端接受，不代表硬件已经执行。只有收到对应`command_id`的设备回执，才允许显示执行成功。

验收时必须分别检查“服务端接受请求”“设备收到指令”“设备执行动作”“最终状态一致”四个节点，任一节点缺失都不得显示为执行成功。

### 8.4 冲突规则

- 手动指令优先于普通自动响应，但不得无提示覆盖L3安全策略。
- 多条自动响应冲突时，按安全等级、时间和场景优先级仲裁。
- L3危险动作不得仅依赖自动安抚作为处理完成。
- 设备离线、低电量或能力不支持时，不下发无法执行的指令。

### 8.5 验收

| 用例 | Given | When | Then |
|---|---|---|---|
| 正常响应 | 设备在线且已授权 | 触发安全响应 | 指令、回执、时间和结果一致 |
| 无回执 | 指令已下发 | 超时未收到回执 | 显示执行未确认并提示人工处理 |
| 用户中止 | 音频正在播放 | 用户点击停止 | 设备停止并返回中止回执 |
| 规则冲突 | 自动响应与手动操作同时发生 | 系统仲裁 | 按规则执行并记录覆盖原因 |

## 9. 功能五：成长报告

### 9.1 元数据

| 项目 | 内容 |
|---|---|
| 需求编号 | RPT-001 |
| 优先级 | P1 |
| T0状态 | 【部分实现】事件汇总、LLM生成、兜底与入库链路存在 |
| T0.1目标 | 报告事实可追溯、生成方式透明、失败可降级 |

### 9.2 报告内容

- 报告周期、数据覆盖率和设备离线时段。
- 睡眠片段、总时长及状态切换。
- 哭闹次数、持续时间、告警和家长反馈。
- 危险/关注事件及处理结果。
- 成长里程碑和家长主动记录。
- AI摘要及非医疗声明。

### 9.3 生成规则

- 结构化指标由确定性计算生成，LLM不得改写基础统计值。
- LLM输入仅包含授权且必要的数据摘要。
- AI描述必须能够关联来源事件；不得生成疾病诊断或确定性健康结论。
- 数据不足时显示数据覆盖情况，不生成误导性趋势。
- 外部服务失败时生成规则化摘要，并记录生成方式和失败原因。
- 用户纠错生成新版本，保留原版本和修改记录。

### 9.4 异常与权限

| 异常 | 处理 |
|---|---|
| 数据不足 | 生成简版数据概览或提示暂不生成 |
| LLM失败 | 使用结构化模板兜底 |
| 内容事实错误 | 支持反馈、纠错和重新生成 |
| 无分享权限 | 阻止分享并提示管理员授权 |
| 外部服务不可用 | 不影响告警及核心看护链路 |

### 9.5 验收

| 用例 | Given | When | Then |
|---|---|---|---|
| 正常生成 | 周期内数据充分 | 请求报告 | 统计值可追溯至事件，AI摘要有版本记录 |
| 数据不足 | 大量离线或无有效数据 | 请求报告 | 展示覆盖率，不生成确定性趋势 |
| AI失败 | 外部LLM不可用 | 请求报告 | 返回规则化摘要并标记生成方式 |
| 用户纠错 | 报告存在事实问题 | 提交纠错 | 生成新版本并保留修改记录 |

## 11. 三类核心场景详细规格

### 11.1 熟睡场景 SLP-001

#### 目标

稳定识别熟睡片段，用于实时状态和睡眠报告；该能力不是医疗睡眠监测。

#### 输入与候选规则

| 输入 | 原始候选值/条件 | 当前状态 |
|---|---|---|
| 呼吸率 | 12—20次/分 | 【原始规划｜需专业与设备验证】 |
| 心率 | 稳定；草稿另有50—90次/分 | 【存在口径差异】 |
| 活动/位移 | 位移小于5厘米并持续 | 【候选规则】 |
| 时间窗口 | 原材料出现10分钟和30分钟 | 【冲突，T0.1必须统一】 |
| 环境声音 | 小于30dB | 【需设备距离和环境校准】 |
| 姿态 | 躺卧且持续稳定 | 【候选规则】 |

#### 事件状态机

```text
未知/清醒 → 疑似熟睡 → 熟睡成立 → 疑似苏醒 → 清醒
任意状态 → 数据无效/离线 → 状态待判断
```

#### 规则要求

- 必须使用连续有效数据窗口，不以单帧确认熟睡。
- 触发阈值与退出阈值分离，避免频繁切换。
- 短暂动作可进入迟滞窗口，不立即结束睡眠片段。
- 数据缺失时不得默认输出熟睡。
- T0.1阈值由受控测试确定，原始数值不作为医学标准。

#### 目标指标

| 指标 | T0.1建议门槛 |
|---|---:|
| 事件级Precision | ≥90% |
| 事件级Recall | ≥90% |
| F1 | ≥90% |
| 漏报率 | ≤10% |
| 错误状态切换 | ≤1次/小时 |

### 11.2 哭闹场景 CRY-001

#### 目标

识别持续哭闹并进行分级提醒，同时控制环境声音导致的误告警。

#### 输入与原始候选规则

| 等级 | 原始候选条件 | 产品处理 |
|---|---|---|
| L1 | 40—55dB＋生命体征相对稳定＋轻微表情 | 普通提醒或记录 |
| L2 | 55—70dB＋动作，持续30秒可触发预设音频 | 强提醒，响应需授权 |
| L3 | 高于75dB＋生理变化/剧烈动作 | 疑似高风险，要求人工查看 |

#### 规则要求

- 分贝阈值需结合麦克风距离、噪声、设备型号完成校准。
- 声音模型为主要输入，表情和动作可作为辅助证据。
- 电视、成人说话、笑声及其他儿童哭声作为困难负样本。
- 连续哭闹合并为一个事件，短暂停顿按合并窗口处理。
- 自动播放家长音频前需明确授权，并支持中止和执行回执。
- 家长反馈“真实、误报、无法判断”进入评估数据。

#### 目标指标

| 指标 | T0.1建议门槛 |
|---|---:|
| 事件级Precision | ≥85% |
| 事件级Recall | ≥90% |
| F1 | ≥87% |
| 漏报率 | ≤10% |
| 非哭闹误告警 | ≤1次/8小时/设备 |
| 有效事件P95发现时间 | ≤10秒，起点为满足持续判断条件后 |

### 11.3 危险动作场景 DNG-001

#### 目标

优先发现可能导致跌落或翻越护栏的危险动作，并通过L3告警促使照护者立即查看。

#### 子场景范围

| 子场景 | T0.1处理 |
|---|---|
| 靠近床沿/护栏 | 候选风险，可作为前置特征 |
| 攀爬护栏 | P0验证候选 |
| 身体越过护栏 | P0验证候选，优先作为主验收场景 |
| 危险站立 | P1，需结合位置和月龄 |
| 疑似呼吸异常 | 单独立项评审，不并入视觉危险动作统一门槛 |

#### 输入与原始候选规则

- 身体重心距安全区边界约20厘米。
- 翻滚角度大于90度。
- 躯干高度超过护栏高度一半，重心方向向上或向外。
- 头部或上半身投影越过护栏边界。

以上均为【原始候选规则】，需结合摄像头标定、床体坐标系、人体关键点误差和受控测试重新确认。

#### 候选事件与正式事件

```text
任一风险特征命中 → 疑似危险候选
多特征或连续帧成立＋数据质量有效 → 危险事件成立
→ 创建L3告警 → 用户确认/升级 → 安全状态持续成立 → 事件关闭
```

#### 规则要求

- 危险动作可采用相对敏感的候选阈值以提高Recall。
- 必须通过空间位置、动作方向、持续时间或其他模态控制误报。
- 画面遮挡但存在风险线索时输出“无法确认的疑似异常”，要求人工查看。
- 有成人抱起等干扰条件时不得直接生成确定性危险结论。
- L3事件保留触发快照、关键数据、规则/模型版本和完整处理链。
- 危险样本使用假人、模拟装置、合规历史数据等方式采集，不让真实婴幼儿执行危险动作。

#### 目标指标

| 指标 | T0.1建议门槛 |
|---|---:|
| 事件级Precision | ≥80% |
| 事件级Recall | ≥95% |
| F1 | ≥87% |
| 漏报率 | ≤5% |
| 非危险误告警 | ≤1次/24小时/设备 |
| 事件成立后L3告警P95送达时间 | ≤3秒 |

## 12. 指标与评测口径

### 12.1 基础定义

- `Precision = 正确识别的目标事件数 ÷ 系统识别为该场景的全部事件数`。
- `Recall = 正确识别的目标事件数 ÷ 真实发生的该场景事件总数`。
- `F1 = 2 × Precision × Recall ÷（Precision + Recall）`。
- `漏报率 = 1 - Recall`。
- 严格误报率FPR不等于`1 - Precision`；产品侧同时统计单位时间误告警次数。

### 12.2 评测规则

- 以完整事件为主要统计单位，帧级指标作为算法诊断数据。
- 冻结事件开始、结束、合并和匹配容差后再评测。
- 训练、验证和测试数据按宝宝/家庭隔离，避免身份和环境泄漏。
- 分别报告白天、夜间、遮挡、噪声、设备型号和月龄切片结果。
- 每个核心场景首轮建议不少于100个独立正事件，并配足正常及相似负样本。
- 同时披露样本量、类别分布、置信区间、模型/规则版本和数据来源。
- 阈值在验证集选择，在独立测试集确认，不能反复使用测试集调参。

### 12.3 模型阈值原则

- 每个标签设置独立阈值，不统一使用Top1或统一分数线。
- 危险候选阈值可相对敏感，但正式告警需通过时序与风险规则。
- 低于有效阈值时输出“不确定”，不得强制归类。
- Top3用于调试、人工复核和混淆分析，不作为唯一产品决策。

## 15. 阶段结论

T0已有六个核心模块的产品与工程结构，但成熟度不同。T0.1应优先补齐设备在线、实时数据、三类场景事件、告警回执和人工处理链路；场景响应、成长报告和AI陪伴分别以真实硬件回执、事实可追溯和P0链路隔离作为验收边界。

九大场景继续作为用户可理解的产品语义，但底层采用多维事实标签能够更准确表达“熟睡＋趴睡”“站立＋哭闹＋危险动作”等并发状态。最终验收必须从模型标签继续追踪到事件成立、消息送达、用户确认和处理结果，不能以模型单次识别分数替代产品闭环结果。
